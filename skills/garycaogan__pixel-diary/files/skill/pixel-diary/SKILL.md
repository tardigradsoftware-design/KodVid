# 像素日记：对标复刻和分集生产

这套方法把一条“像素角色 + 对话框”类的爆款拆开，换成你自己的角色和台词，用代码一帧一帧渲染出来。画面、动画、打字音和配乐全部由一份分集 JSON 生成，改一句台词重出一条只要一分钟左右，不花视频模型的钱。

引擎在本仓库的 `pixel_diary/`，命令都在仓库根目录执行，Python 用仓库自己的 `.venv`。

## 什么时候用，什么时候别用

适合：信息靠文字和画面元素传达、角色站着说话、节奏靠打字和弹出元素推进的视频，比如 AI 运营日记、角色自我介绍、规则说明、数据账本、评论区点菜。

不适合：需要真人、实拍、复杂动作或镜头运动的视频，那类用视频模型做。

## 流程

按顺序做，每一步的细节在 `references/` 里，用到时再读。

1. **拆对标**（`references/teardown.md`）
   - 拿到原片的数据、热评、同题跟风号的数据和逐镜头分镜表。
   - 判断它到底靠什么火：先看选题和人设，最后才看制作。
   - 先查饱和度：同题已经有一堆跟风号、跟风号又不涨粉，就不要原样复刻，只偷内核，换一个变量。
2. **节拍映射**
   - 把原片拆成一张节拍表（时间、画面、台词、作用）。
   - 做 A 版：照原片的事件链一步步来，角色和台词换成自己的。
   - 做 B 版：只改评审里定下的那一个点，其余不动。
   - 台词照原片的作用重写，不搬原句。
3. **角色**（`references/characters.md`）
   - 先用图像模型画草稿，几个角色画在同一张图里，画风才统一。
   - 用 `python -m pixel_diary.sprite` 压成像素，同一组角色用同一个 `--cell`。
   - 写 `face.json`，再用 `python -m pixel_diary.faces` 逐像素画出表情差分，每个表情自动带一张张嘴的说话帧。
4. **写分集 JSON**（`references/episode.md`）
   - 场景类型、字段、线索（cue）、表情代码和长度规则都在这个文件里。
   - 写完先跑 `python -m pixel_diary check 分集.json`。
5. **出片**
   - `python -m pixel_diary build 分集.json --out work/名字 --render out/名字.mp4`
   - 构建会生成 HyperFrames 项目，渲染后自动做响度归一（-16 LUFS）。
   - 改完台词只需要重跑这一条。
6. **质检**（`references/qa.md`）
   - 先用 `npx hyperframes snapshot` 抽关键帧，自己看一遍。
   - 再让能看视频的模型把原片和成片放在一起比，只挑问题。
   - 照问题改，再出一版。

## 规矩

- 不要原样搬别人的台词、角色设计和画面。偷的是结构和机制，不是内容。
- 片子里写明 AI 生成；用到真实 AI 产品的名字时，加“同人创作、非官方账号”的声明。
- 说“画是用代码画的”这类话之前先核对事实：草稿是图像模型画的，就照实说。观众会去对比账号简介。
- 不拿平台封号、地区限制开玩笑，不贬低真实公司，不碰政治。
- 声音：打字音和配乐都由引擎合成，无版权问题。想换成平台曲库的配乐，就在发布时由平台加，或者自己准备一个 wav 替换 `assets/audio/bgm.wav`。

## 常见坑

- 只有音乐、没有人声的原片，Whisper 会编出“字幕志愿者”“作曲 李宗盛”之类的字。看到这种转写，就当它没有配音。
- B 站接口在命令行直接请求会返回 412，要用登录过的浏览器页面里的 `window.__INITIAL_STATE__`，或者用 yt-dlp。
- 立绘轮廓细的草稿直接压会丢线，加 `--thicken 3`。
- 眼睛里和头发同色的像素，闭眼时会残留成“眼泪”。把那个颜色从 `face.json` 的 `keep` 里去掉。
- 第 0 帧就要有标题，不要让开场空着；第 0 帧也别正好在眨眼。
