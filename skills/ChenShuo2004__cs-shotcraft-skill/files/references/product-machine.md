# 那台机器必须是真的

片子里那个窗口，是观众唯一会盯着看的东西。它一假，前面所有的功夫都白费。

禁止低质量仿制。两条合格路径：

1. **按产品真实逻辑像素重画**（默认：可动、可插值、推近到 1.4× 仍清晰）。
2. **无头浏览器 2× 真机截图**（流程复杂、数据真实性本身是卖点、或 2.5D PageCam 需要整页纹理时）。

手搓示意图级 UI——把 13px 的字画成 20px、栏宽随手估、图标换了一套字重——一律禁止。非复刻场景（抽象开场 / 品牌段 / 页面上不存在的独立展示组件）允许手搓，但必须达到出版级质感；达不到就回截图或重画。

## 设计 token：全部有出处

`src/design.ts` 的每一个颜色都逐个抄自产品自己的 token 文件（`_tokens.css` / `theme.css` / tailwind config / Figma variables / 计算样式），**片子里不允许出现第二套颜色**。加注释写清楚出处。

顺手放两个工具函数：`withAlpha(color, a)`（要能吃 `rgb()`，因为主题插值产出的是 `rgb()` 而不是 `#rrggbb`）、`mix(a, b, p)`。

**强调色是配额制。** 挑一个 accent，规定它全片只出现在哪几个地方。深色场里要换一个提亮的变体——暗底上的深红会糊成一团黑。

走模板或镜头卡时，只继承镜头结构与运动语法；字体、排版、配色与材质必须按目标产品重新蒙皮。Ink Press 的琥珀纸张不是默认皮肤。

## 按逻辑像素画，再整体缩放

窗口组件用产品**真实的数值**搭：栏宽 224 / 336、工具栏 46、圆角 20、正文 15.5×1.9——然后靠摄影机的 `k` 决定它在屏幕上多大。不要「因为要拍片，所以把字画大」。

栏宽比例、图标字重、圆角、阴影分层，任何一处偷懒观众说不出哪里不对，但会觉得像个模板。

按钮位置这种**两处都要知道**的坐标（指针要落上去、工具栏要画在那儿），在 `story.ts` 里导出一个常量，两边都引它。写两遍必然会错开。

## 图标

重画产品同一套字形（Phosphor / Lucide / SF Symbols 的同名图标），放在 `components/Icons.tsx`，**不引第三方图标库**：库里的字重、圆角末端只要差一点，整台机器就像素级地不对。产品自己就是从图标包抠文件的，写个脚本从同一个包抠同一批，别手描。

## 重画 vs 抓真机截图

**默认重画。** 主题切换能做成「每一帧都是一套真实存在的配色」。

**以下情况抓图：** 模拟器跑出来的赛果、真实网络请求回来的内容、2.5D PageCam 需要全页纹理 + 元素切片 + `layout.json`。用 Playwright 驱动 dev server，2 倍分辨率截图存进 `public/shots/` 或 `public/textures/`。采集脚本用 `$SKILL/assets/scripts/capture-template.mjs`，改 BASE 与选择器。脚本要能重跑：按可见文本点按钮、失败时把当前路由和可见按钮打出来。

截图前等待：`document.fonts.ready` + 600ms settle；实时同步页再等 1.5–2s；`networkidle` 失败不要假装成功——头像没落地会退化成首字母方块。

两条路可以混：窗口重画，窗口里的某一张图/某一段图表用抓的。

页面数据按风险处理：公开演示数据只有在产品简报明确确认后才可保留；客户、个人、内部、密钥、实时或其他敏感数据必须用虚构或脱敏内容，且在采集前冻结。

## 写死的宽度和字符区间，必须出图验

Remotion 每一帧都是一次全新的 React 渲染，靠 ref 量出来的宽度在第 0 帧永远是 0。所以「这段文字有多宽」只能写死成 em（等宽体一个字符约 0.6em，中文一个字约 1em）。给错了不报错，只会静静地少切或多切一段。

按字符区间标注的内容同理。**凡是写死的区间，改完必须出一张那一帧的图看一眼。**

## 片子里的内容也要对得上

示例文章的两种形态（编辑器里的 Markdown、预览里的成稿）必须是同一篇稿子。agent 对话里的文件名、文件树里的文件名、工具栏上的文档名，三处必须一致。

对话内容也要像真的：请求具体，回答是做完之后的汇报，中间有真实的工具调用序列。写成「正在处理…完成 ✅」就露馅了。文档类镜头的 mock 要出版级，见 aesthetic-rules Q10。
